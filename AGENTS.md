# Repository Guidelines

## Project Overview

`open-ak-blog-template` is a bilingual, content-driven blog built with Next.js 16, React 19, TypeScript, and `@swufefox/ak-ui-react`. Markdown posts are parsed and rendered during the production build; the site also needs a Node.js runtime for locale routing, image delivery, and its custom 404 route.

## Architecture & Data Flow

- `content/posts/*.md` holds the default-locale posts; `content/posts/<locale>/*.md` holds translations with matching slugs. YAML front matter is parsed and validated by `src/lib/posts.ts`, which supplies localized post and archive data.
- `src/lib/markdown.ts` runs the remark/rehype pipeline and returns rendered HTML plus the heading table of contents. It handles standard Markdown and the custom `data`, `stats`, `mermaid`, `sketch`, and `echarts` fences. The pipeline removes raw post HTML before converting generated HTML nodes.
- App Router pages render the home page, posts, archives, search, and feeds. Sitemap and robots routes are generated from the same site/content configuration. `src/lib/urls.ts` builds canonical and locale-aware links.
- `next.config.ts` rewrites default-locale URLs to the locale route; `src/proxy.ts` redirects prefixed default-locale URLs back to the canonical root paths.
- Keep browser behavior in small client components. Theme controls, search filtering, code-copying, and chart rendering hydrate in the browser; Mermaid and ECharts are loaded only when a post uses them.
- Route components that render ak-ui primitives should import server-renderable exports from `src/components/ak.ts`. The package entry touches `createContext` at module scope. Keep `AkMobileMenu` in the client-side `src/components/site-nav.tsx`; its IDs need the existing post-hydration mount workaround.

## Development Commands

```sh
npm ci
npm run dev          # local development at http://localhost:3000
npm run lint         # ESLint over src/
npx tsc --noEmit    # direct type check; no package script is defined
npm run build        # production build and content/Markdown validation
npm start            # serve the production build with next start
```

Set `NEXT_PUBLIC_SITE_URL` before `npm run build` when building for a real domain; canonical URLs, RSS, and sitemap use it. See `docs/deploy.md` for deployment and port settings.

## Code Conventions & Common Patterns

- TypeScript is strict. Use the `@/*` alias for imports from `src/`; keep React component exports PascalCase and file names kebab-case.
- Put template identity, locale list, navigation, and other site-level options in `src/site.config.ts`. Use `src/lib/urls.ts` for internal links rather than constructing locale paths in components.
- Keep article validation in `src/lib/posts.ts`. Invalid required metadata, dates, YAML, or tag lists should fail with the source filename in the error so a broken post is found during build.
- Keep filesystem reads in async server/build-time code (`node:fs/promises` in `posts.ts`); pass loaded values to browser components as props. `posts.ts` caches the collection at module scope.
- Preserve the Markdown plugin order in `src/lib/markdown.ts`; raw HTML is stripped before `rehypeRaw` processes HTML generated by the pipeline. Add custom fenced-block behavior there and document author-facing syntax in `docs/writing.md`.
- Keep dependencies explicit through function arguments and component props. There is no configured dependency-injection container; shared site settings come from the typed `siteConfig` module.
- Keep UI state local to client components. Follow existing React subscription/hydration patterns (including `useSyncExternalStore` in `site-nav.tsx`) when server and browser output must agree.
- Prefer contextual errors over silent recovery for invalid content. Unknown routes use `notFound()`; metadata/content errors should identify the input file.
- No formatter is configured. Match nearby formatting and use ESLint as the style check.

## Important Files

- `src/site.config.ts` — site identity, locale definitions, and navigation settings.
- `src/lib/posts.ts` — post discovery, front matter validation, locale filtering, and draft behavior.
- `src/lib/markdown.ts` — Markdown plugins, custom content blocks, and TOC generation.
- `src/lib/urls.ts` — canonical locale-aware route builders.
- `src/proxy.ts` and `next.config.ts` — default-locale redirect and rewrite behavior.
- `src/components/ak.ts` and `src/components/site-nav.tsx` — ak-ui server boundary and mobile-menu hydration handling.
- `package.json`, `package-lock.json`, `tsconfig.json`, `eslint.config.mjs` — scripts, locked dependencies, compiler, and lint configuration.
- `docs/architecture.md`, `docs/writing.md`, `docs/configuration.md`, and `docs/deploy.md` — implementation, authoring, setup, and deployment details.

## Runtime/Tooling Preferences

Use Node.js 20.9 or newer and npm with the committed `package-lock.json`. The project pins Next.js 16.4.6 and React 19. Do not assume this version follows older Next.js conventions. The app uses `src/proxy.ts`, rewrites, and runtime route handlers; ordinary `next start` deployment is supported, while static export requires the migration described in `docs/deploy.md`.

## Testing & QA

- No test runner, test script, or test dependencies are configured. `npm test` is not available.
- For code changes, run `npm run lint`, `npx tsc --noEmit`, and `npm run build`. The build exercises post metadata parsing and Markdown rendering against the real content collection.
- After route or browser-interaction changes, run `npm start` and smoke the affected routes in a browser. Include both the default locale and `/en` when locale behavior changes; verify the relevant post, archive/search, feed, or 404 route as applicable.
